# GTNH 移植方向

## 已定方向

- 以最低后续同步成本为首要约束，参照最新规范源码；旧版本仅用于 API 对照。
- 同仓库、独立旧版构建，直接共享算法，使用窄平台接缝；不维护第二份地图引擎或模拟现代 Minecraft API。
- CPU 优先、离线验证优先；先完成真实地形 L0 显示，再推进更新/持久化 L1、完整交互与 GPU。不预建 Vulkan 后端。
- 先以原版外观验证平台接缝，Mod 方块/实体兼容仍在迁移范围内；完整一轮迁移后再开展客户端与逐步扩展 Mod 环境的验收，离线通过不代表可发布。
- 产品行为以 Xaero 为第一参照、JourneyMap 为第二参照；参照不等于依赖或数据联动。JourneyMap 并装兼容在后续客户端验收，不复制或分发其闭源实现。

## 程序结构

- 根 `src/main` 保留规范实现；`gtnh/` 隔离旧版构建、入口与平台适配。
- [选源清单](../gtnh/source-policy.json) 明确共享与平台类；每个 FQN 只编入一份，不提交生成源码。
- 采集与外观准备在主线程；后台只消费已准备的数值快照、外观数据和世代 token。UNKNOWN 不等于 AIR，过期结果不得合并。
- 世界、资源与 GPU 生命周期属于平台层；地图数学和 CPU 烘焙尽量共享。

## 依赖取舍

- 基础环境为 Java25、Forge1614、lwjgl3ify、GTNHLib、UniMixins；构建版本由配置固定，见[构建入口](../gtnh/README.md)。
- Angelica 属于可选兼容，不依赖其渲染内部实现。
- UI 保留 Diorama 自有行为；ModularUI2 仅为设置/路点薄壳候选，尚未引入。

目前仅本机开发：仓库只保留必要且低频变化的说明；过程备忘、研究与运行证据放本地，不维护逐阶段报告。交接文档仅在用户明确要求时编写，也只放本地。
