# GTNH 移植方向

## 已定方向

- 以最低后续同步成本为首要约束，参照最新规范源码；旧版本仅用于 API 对照。
- 同仓库、独立旧版构建，直接共享算法，使用窄平台接缝；不维护第二份地图引擎或模拟现代 Minecraft API。
- 优先恢复 Diorama 的特色：跑图和地形变化时仍然流畅的 3D 小地图。先跑通增量 CPU 路径，再判断何时接 GPU；不预建 Vulkan 后端。
- 离线开发与实机验收分开：无实机窗口时继续完成可离线交付的步骤，不把游戏、GL 或性能验收标记为通过。
- 产品行为以 Xaero 为第一参照、JourneyMap 为第二参照；参照不等于依赖或数据联动。JourneyMap 并装兼容在后续客户端验收，不复制或分发其闭源实现。

## 迁移路线与过关条件

**起点**：独立构建、真实地形 L0、有界变更刷新、L1 和单人预览缓存、可改绑快捷键与 CPU HUD 已接入。HUD 和全屏预览尚未共用同一个瓦片缓存与调度器；现有整瓦片路径保留为对照和回退。逐版本状态及运行证据只放本地备忘。

| 顺序 | 实现切片 | 过关条件 |
| --- | --- | --- |
| 1 | **采集与计量**：把预检与快照的重复逐格读取收敛到同一批脱离世界的区段数据。保留 loaded-only、预算、方块外观准备和世界/资源世代护栏。分开记录采集、排队、烘焙、上传的量与耗时。 | 同一输入的新旧快照、染色与光照等价；缺区块不触发加载，未知不当空气；离线可检查读取次数和队列预算。此步不宣称帧率提升。 |
| 2 | **CPU 增量瓦片**：先移植上游投影脏区和逐瓦片版本，再接共享 CPU 局部烘焙及渲染线程局部上传。带上阴影、光照和轮廓的影响范围；新瓦片、大范围变化或无法安全局部更新时整张重烘。 | 同一快照的局部合并与整张重烘在受影响范围内一致；区块边缘无漏刷，无关事件不使任务作废，新变更不被旧结果覆盖；离线核对上传矩形和每帧提交预算，真实 GL 留给第 5 步。 |
| 3A | **统一地图会话**：让 HUD 与大地图共用瓦片调度、缓存和近处优先级；大地图依次恢复平移、缩放、回到玩家和按需 L1。将单人像素缓存接入统一会话，磁盘 I/O 不占可见瓦片的烘焙队列；联机持久化等可靠世界身份，不按裸地址混存。 | 同一瓦片不因切换 HUD/大地图重复烘焙；换世界或资源重载丢弃旧任务；退出重进能恢复已保存区域，未探索和缺失区域不会擦掉历史地图。 |
| 3B | **外观覆盖**：可与 1–3A 并行。以普通主世界中会阻断采集的方块为优先，先补常见原版形状和透明类，再扩展到可复用的 Mod 外观适配；特殊渲染器与方块实体另列。 | 用代表性区块夹具验证外观与已知覆盖，先收敛确认会阻断普通世界的缺口；不把所有 Mod 兼容当作进入下一阶段的条件，也不以逐 Mod 颜色表替代适配。 |
| 4 | **恢复主要地图行为**：先路点与基础设置，再扩展多维度/洞穴和对应的地图身份。雷达、绘图/测距、存档填图和网络共享单列，不阻塞主世界小地图。 | 各项有独立场景与离线回归；按键冲突、GUI 和重进后的行为列入客户端验收。行为按 Xaero、JourneyMap、Diorama 的既定差异判定，不引入联动依赖。 |
| 5 | **CPU 客户端验收**：核心迁移完成且有测试窗口后，依次验证基准客户端、GTNH 代表性环境、可选渲染器/并装。固定普通世界、连续跑图、放拆方块、重进和资源重载场景。 | 建立 CPU 基线，分别记录采集耗时、更新到可见的延迟和帧时间尾部；确认普通世界覆盖、地图连续性、持久化和 GL 状态。没有运行证据，保持“未验收”。 |
| 6 | **可选 GPU 烘焙**：CPU 基线通过后，先用同一份数值输入做主世界窄原型，再接多遍渲染、异步回读和故障回退。GPU 显示现有瓦片不算 GPU 烘焙。 | 同场景比较 CPU/GPU 的像素差异、端到端延迟与帧时间尾部；能力不足、读回失败或收益不明确时保留 CPU 默认，不以着色器能编译作为启用条件。 |
| 7 | **整合与发布决策**：扩展代表性 Mod 方块/实体及可选渲染器矩阵；确认 Java/依赖支持承诺，并做一次真实上游同步演练。 | 产物、运行环境与兼容边界都有证据；是否发布、推送或部署另行授权。GPU 若保持关闭，不阻塞 CPU 版本的发布评估。 |

**执行规则**：按“交付物 + 过关条件”推进。已通过的切片不重做，只跑被本次改动触及的回归；外观兼容和非核心交互不无限扩张。离线主线顺序是 **1 → 2 → 3A → 4**，3B 独立推进；需要实机的门槛不阻塞后续可离线工作，但在通过前不能宣称性能或兼容性达标。

## 程序结构

- 根 `src/main` 保留规范实现；`gtnh/` 隔离旧版构建、入口与平台适配。
- [选源清单](../gtnh/source-policy.json) 明确共享与平台类；每个 FQN 只编入一份，不提交生成源码。
- 采集与外观准备在主线程；后台只消费已准备的数值快照、外观数据和世代 token。UNKNOWN 不等于 AIR，过期结果不得合并。
- 世界、资源与 GPU 生命周期属于平台层；地图数学和 CPU 烘焙尽量共享。

## 依赖取舍

- 基础环境为 Java25、Forge1614、lwjgl3ify、GTNHLib、UniMixins；构建版本由配置固定，见[构建入口](../gtnh/README.md)。
- Angelica 属于可选兼容，不依赖其渲染内部实现。
- UI 保留 Diorama 自有行为；ModularUI2 仅为设置/路点薄壳候选，尚未引入。

目前仅本机开发：仓库只保留必要且低频变化的说明；过程备忘、研究与运行证据放本地，不维护逐阶段报告。交接文档仅在用户明确要求时编写，也只放本地。
