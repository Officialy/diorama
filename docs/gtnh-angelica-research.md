# Angelica conveniences for the Diorama 1.7.10 port

Research snapshot: 2026-11-10. **Recommendation: independent renderer first; narrow, optional Angelica integration second.** Angelica is useful compatibility evidence, not an appropriate mandatory rendering framework for the Java 25 + lwjgl3ify baseline.

## Scope and reproducibility

- Requested release `2.1.50` resolves to **d1e6dc8c9463eda8bab1b80383cac17321b0535a**, commit dated 2026-07-04.
- Current upstream at inspection resolves to **60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4**, commit dated 2026-11-08, “Restore FluidLogged fluid rendering (#2354)”. “Current” below means this immutable pin, not a promise about future master.
- All substantive source citations below are immutable upstream URLs; no local reference checkout or machine path is required to read this report.
- This was source inspection only: **no build, compilation, runtime compatibility test, game launch, installation, or Minecraft-instance modification was performed**. In particular, Java 25 suitability is a required baseline, not something this research proved.

## Decision matrix

| Facility | 2.1.50 / current evidence | Recommended use |
|---|---|---|
| Texture animation activity | Same public `TextureServices` entry points in both | **Yes, optional bridge** to mark atlas icons used by Diorama active. Not a texture allocator. |
| Shader-pack status / shadow pass | Iris public v0 API in release; current also offers Angelica shader facade | **Yes, optional status query**; version/capability gate. Not shader pipeline ownership. |
| GL state reading | Current has explicit read-only `angelica\|glstate` API v1; absent in release | Current-only diagnostic/fog/matrix bridge if needed. Not baseline state restoration. |
| GL state write/restore | Release monolithic GLSM; current split GLSM and StateSet scopes | **No direct shared dependency**. Use normal transformed GL calls and Diorama-owned explicit state scope. |
| GL adapters, FBO/shader/buffer wrappers | Backend and Iris/GLSM implementation classes | **Study, do not import/shade** into baseline. |
| HUD lifecycle | ClientEvent pre/post hooks in both; private timer-driven cache | **Optional POST_RENDER_HUD bridge** for live overlay; avoid mutating cache internals. |
| Render scheduling | AngelicaRenderQueue in both | Internal; own bounded baseline queue, no mandatory dependency. |
| World snapshots / biome blending / terrain mesher | WorldSlice and Celeritas classes | Study snapshot/threading pattern; do not use as general model exporter. |
| TESR mesh cache API | Current explicit API v3; absent in release | Optional future TESR optimization only, not terrain/model capture for the port. |

## 1. GL state management and restoration

### What actually exists

Release [GLStateManager:3306–3482](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/GLStateManager.java#L3306-L3482>) implements cached state, lazy push/pop state stacks and a `glPushAttrib/glPopAttrib` replacement. Restoration actively reissues driver calls. This is not a passive utility: it participates in legacy GL emulation, display-list recording and Angelica's shader/cache generations. A generic attribute push does **not** constitute a complete modern GL transaction (program, VAO, buffers, FBO and matrix contents need separate coverage).

Current moved most operations into separate GLSM classes. [GLSMAttribStack](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/GLSMAttribStack.java>) now exposes `pushState(StateSet)` / `popStateTo(depth)` and retained exit state; [StateSet](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/StateSet.java>) defines selected scopes such as BATCH, FONT and HAND. These are implementation-specific state selections, not a universal save-everything contract. Current [HUD compositing:126–150](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/hudcaching/HUDCaching.java#L126-L150>) still explicitly saves/restores program and VAO around an attribute scope. Do not assume either release's push/pop has the other's semantics.

Current [GLState](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/glstate/GLState.java>) is explicitly **read-only, render-thread-only**: fog values, copied model-view/projection matrices, backend name and thread query. [GL-state API declaration](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/glstate/package-info.java>) declares API version 1. This API does not exist at 2.1.50 and provides no restoration handle.

### Practical port recommendation

- Own a small renderer/state scope with `try/finally`. Capture the actual incoming read/draw FBO, viewport/scissor, program, VAO, buffer bindings touched, active texture and touched texture/sampler bindings, blend functions/equations, depth state/write mask, cull/color masks and pixel-store settings touched. Preserve matrix stacks/mode separately if invoking legacy rendering. Restore **incoming values**, not guessed vanilla defaults.
- When Angelica is present, normal Java GL calls through the transformable mod classloader are the supported interception path. Do not bypass its tracked state with native calls, reflective GL invocation, or an untracked raw backend for “speed”. Driver state and Angelica's cache must remain coherent.
- [Release GLRedirects](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/api/GLRedirects.java>) documents that scripts/reflection/MethodHandles bypass normal transformation and need explicit redirection. Current [GLRedirects](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/GLRedirects.java>) changed the target scheme from one GLStateManager owner to per-method owners and adds `getTargetReference/redirectScript`. Even a public class here has evolved incompatibly: do not hardcode its old TARGET_CLASS mapping for both pins.
- A direct-LWJGL3 `@Lwjgl3Aware` renderer needs a deliberate Angelica compatibility boundary. Do not assume all GL*C calls will be tracked automatically. Prefer the baseline's transformable legacy-API entry points where sufficient; if direct calls are essential, verify interception/version behavior before enabling optional integration. This research did not run that validation.

## 2. LWJGL2/3 adapters: useful examples, wrong dependency boundary

Release [LWJGL3 backend:42–138](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/lwjgl3-backend/src/main/java/com/gtnewhorizons/angelica/lwjgl3/Lwjgl3GLRenderBackend.java#L42-L138>) is annotated `@Lwjgl3Aware`, calls GL*C directly, checks GL31C availability and advertises priority 50. The separate LWJGL2 backend uses the old binding API. Current [BackendManager](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/backend/BackendManager.java>) uses ServiceLoader, selects available highest-priority implementations, and initializes the selected backend. These classes depend on Angelica's GL abstraction and startup/context lifecycle, not merely on lwjgl3ify.

Current [GLSM startup contract](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/GLStateManager.java#L45-L50>) requires a current GL context before loading/initializing its manager. [RenderSystem capability initialization](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/RenderSystem.java#L77-L203>) selects DSA implementations, checks individual capabilities and core/GLES behavior. [lwjgl3ify transformer exclusions](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/loading/Lwjgl3ifyExclusions.java>) further demonstrates integration with RFB transformation internals.

**Reuse the ideas:** isolate binding differences, resolve capabilities after context creation, use explicit feature fallbacks. **Do not reuse the machinery:** no Angelica backend startup, replacement GL manager, ServiceLoader backend registration, transformer exclusions or native libraries should become necessary to render Diorama. Java 25 does not imply any particular GPU GL capability. Query the actual context and offer an ordinary GL3-style path before optional DSA/persistent storage features.

## 3. Texture, shader, buffer and FBO helpers

### Good narrow API: texture activity

[Release TextureServices](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/api/TextureServices.java>) and [current TextureServices](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/TextureServices.java>) are identical at inspection. `updateTextureAnimation(IIcon)` checks Angelica's sprite extension and marks the sprite active; `updateBlockTextureAnimation(IIcon, RenderBlocks)` records icons used by compatible RenderBlocks. This is useful when map rendering uses atlas animations without the usual visible-world terrain path. Keep calls optional; without Angelica the bridge is a no-op. This does not provide image extraction, atlas ownership, reload tracking or off-thread animation permission.

### Status query, not custom-shader service

Release [IrisApi v0](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/net/irisshaders/iris/api/v0/IrisApi.java>) has a documented revision query plus `isShaderPackInUse()` and `isRenderingShadowPass()`. Prefer this narrow public interface over internal Iris pipeline fields when release compatibility needs status. Current [ShaderPacks](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/shaders/ShaderPacks.java>) adds an Angelica facade for shader use, frame time and begin/end block-entity identity. It is absent in 2.1.50. Neither means “render my minimap safely inside arbitrary shader-pack passes.” Own Diorama's offscreen shader/FBO, and integrate the final HUD composite at a known post-HUD point.

### Internal wrappers to avoid importing

- [GlFramebuffer](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/net/coderbot/iris/gl/framebuffer/GlFramebuffer.java>) owns an FBO, records color attachments, handles depth/stencil attachment format and completeness, and uses GLStateManager/RenderSystem/TextureInfoCache. `getStatus()` binds the FBO; it is not state-neutral. Do not borrow the world's or Iris's framebuffer attachments for Diorama ownership.
- [GlShader](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/net/coderbot/iris/gl/shader/GlShader.java>) compiles and logs shaders with Angelica GLSM/RenderSystem, GLDebug and GlResource. It is not a stable independent shader API. Own compilation/linking error cleanup and shader deletion in Diorama.
- [ShaderStorageBuffer](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/net/coderbot/iris/gl/buffer/ShaderStorageBuffer.java>) couples binding index, ShaderStorageInfo and viewport-relative allocation to Iris. It requires features beyond a simple baseline renderer. Do not use it as the default VBO abstraction.
- HUDCaching's CustomFramebuffer/SharedDepthFramebuffer and captured DirectTessellator/VAO helpers are **GTNHLib** types, not standalone Angelica APIs. If wanted, evaluate a pinned GTNHLib version separately rather than pulling Angelica to obtain them; their independent implementation/API was not audited here.

**Recommendation:** small Diorama-owned texture/program/buffer/FBO owners with explicit create/resize/delete, incomplete-FBO checks and failure cleanup. Store CPU appearance data independently of atlas texture IDs. Do not shade Iris/GLSM helpers; their transitive cache and lifecycle assumptions would remain.

## 4. HUD caching: hooks are useful; invalidation is not an API

Release [HUDCaching:64–108](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/hudcaching/HUDCaching.java#L64-L108>) creates a SharedDepthFramebuffer, refreshes by `1000 / hudCachingFPS` and resizes during refresh. The `dirty` flag is private. There is no public `invalidate()` hook in this implementation. On a cache hit normal `GuiIngame.renderGameOverlay` is skipped, so ordinary Forge overlay handlers do not necessarily execute every visual frame.

However PRE_RENDER_GUI and PRE_RENDER_HUD are posted before the cache branch; POST_RENDER_HUD is posted after compositing, including when caching is inactive. [ClientEvent](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/event/ClientEvent.java>) provides a separate `net.minecraftforge.eventbus.api` bus, **not the ordinary legacy MinecraftForge.EVENT_BUS**. Current [HUDCaching](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/hudcaching/HUDCaching.java>) preserves these lifecycle hooks while substantially changing compositing/state restoration and adding retained state, depth composite shader and crash reset. Those implementation changes do not introduce a general public map-cache invalidation service.

The important framebuffer trap: [Framebuffer HUD interception](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/mixin/java/com/gtnewhorizons/angelica/mixins/early/angelica/hudcaching/MixinFramebuffer_HUDCaching.java>) redirects attempts to bind Minecraft's main framebuffer while cache capture is in progress. **Do not “restore” by always calling Minecraft's main framebuffer.** Preserve the actual entry bindings for offscreen bake passes, particularly if invoked inside an overlay callback.

**Recommended optional integration:** when the Angelica HUD hook is present and actually active, composite Diorama's independent map texture at POST_RENDER_HUD, once per frame; suppress duplicate standard overlay drawing for that mode. Baseline uses normal Forge overlay rendering. Keep a separate map dirty/generation system, so terrain rebakes are decoupled from map camera/marker/UI redraw. Do not mutate Angelica config, reflectively force its private dirty flag, insert Diorama into its cached framebuffer, or copy its hardcoded mod compatibility paths. Test both caching enabled and disabled before accepting the bridge.

Xaero precedent in the inspected source: [release Xaero hook and crosshair workaround](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/hudcaching/HUDCaching.java#L68-L74>) calls XaeroMinimapCore.beforeIngameGuiRender before the cache branch, with a later color reset for its crosshair interaction. This is evidence that minimaps require explicit per-frame integration, **not** a reusable Xaero API or a reason to invoke Xaero internals. Diorama's 3D texture can follow this per-frame composite precedent while keeping its expensive terrain bake independently cached.

## 5. Render-thread scheduling and reloads

[Release AngelicaRenderQueue](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/AngelicaRenderQueue.java>) and [current queue](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/rendering/AngelicaRenderQueue.java>) use ConcurrentLinkedQueue plus an executor that runs immediately on the GL main thread or queues/unparks it otherwise. `processTasks(max)` and `managedBlock` are renderer-owned pumping machinery. Release [deferred meshing:328–348](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/AngelicaChunkBuilderMeshingTask.java#L328-L348>) uses this executor to finish unsafe legacy renderers on the main thread. Current [MainThreadPump](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/glsm/src/main/java/com/gtnewhorizons/angelica/glsm/backend/MainThreadPump.java>) is display/input threading infrastructure, not a public resource-upload dispatcher.

**Do not depend on these internal queues or call their task pumps.** Own a bounded upload/deletion queue drained at a known client render hook; workers produce immutable CPU data only. Tag work with world/dimension/resource generations, discard stale results, cap per-frame work, and avoid blocking the render thread on a worker that awaits render-thread work. With Angelica enabled, ensure the chosen hook really runs on its context-owning render thread; “client tick” alone is not a sufficient GL guarantee.

Release [BlockRenderListManager reload listener](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/items/BlockRenderListManager.java#L51-L59>) registers with Minecraft's IReloadableResourceManager, deletes GL lists and clears its cache. This is an example to follow through the **Minecraft** reload API, not an Angelica reload subscription. The block/meta-only display-list key is an inventory optimization and insufficient for world appearance affected by position, neighbors, biome or tile data.

Recommendation: on resource reload increment Diorama's resource epoch; invalidate icon/UV/appearance/shader caches; retire old GPU resources on the render thread; lazily recreate after resources are ready. Invalidate on world unload/dimension change too. Iris's internal texture reload notifier is not needed and should not be appropriated as a generic mod reload bus.

## 6. Block appearance/model/biome capture

### Available implementation evidence

- [WorldSlice contract](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/world/WorldSlice.java#L38-L60>) snapshots block, metadata, biome and light arrays, with neighbor context for chunk builds. It explicitly says slices cannot be shared concurrently, despite being isolated from main-thread mutation of copied data. Construction/preparation still accesses live world chunks; it is not a universal thread-safe world handle.
- [ClonedChunkSection](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/world/cloned/ClonedChunkSection.java#L52-L118>) includes special LOTR/CubicChunks handling, lighting integration and a mixin-provided concurrent tile-entity map. Tile entities are collected as object references, not serialized immutable deep copies. Importing this class would drag in renderer/compat/mixin assumptions.
- [SmoothBiomeColorCache](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/SmoothBiomeColorCache.java>) adapts Celeritas's biome cache for grass, foliage and water with an active ThreadLocal. Current retains the facility but has configurable-radius handling. It is internal, not a stable biome-color extraction service.
- Release [terrain rendering/capture:309–320](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/rendering/celeritas/AngelicaChunkBuilderMeshingTask.java#L309-L320>) invokes `canRenderInPass` for side effects, then `RenderBlocks.renderBlockByRenderType` and copies raw Tessellator data plus Angelica-specific vertex state. This confirms 1.7.10 appearance is not just modern baked JSON models or six `getIcon` calls. Do not invoke this chunk task to obtain a generic map mesh.
- [ThreadSafeISBRH](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/api/ThreadSafeISBRH.java>) is an opt-in annotation with strict mutable-state/tessellator rules, not proof that arbitrary installed mod renderers are thread-safe. Unmarked/unknown renderer capture should remain on the main render thread.
- [ChunkBiomeDataChangedEvent](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/event/ChunkBiomeDataChangedEvent.java>) can be an optional invalidation hint. Its inspected [producer in MixinChunk](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/mixin/java/com/gtnewhorizons/angelica/mixins/early/celeritas/terrain/MixinChunk.java#L142-L153>) only posts when ground-up client fillChunk updates change a previously initialized biome hash. It is **not** a complete feed of every mod's dynamic biome/color changes. Copy coordinates immediately; the event object is a reused singleton.
- `TintRegistry/TintComputer` concern colored **light** blend modes, not the general biome/block color API; do not substitute them for block colorMultiplier/biome behavior.

### Current public TESR API is a different facility

Current [TESR API declaration](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/tesr/package-info.java>) declares `angelica|tesr` API v3, render-thread only. [TesrMeshProvider](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/tesr/TesrMeshProvider.java>) opts a TESR into keyed cache/batch rendering, supports meshDirty and null-key vanilla fallback, and explicitly documents compile-only + @Optional interface/method guarding. [TesrMeshCache](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/api/tesr/TesrMeshCache.java>) offers renderCached/invalidate. This is a genuine intentional extension point, but **absent in 2.1.50**, and optimizes participating TESRs; it does not export arbitrary terrain meshes or provide map capture.

### Concrete baseline capture approach

Capture block/metadata, light, biome/tint and relevant neighbor context on the client thread into Diorama-owned immutable data. Treat biome/neighbor-dependent appearance separately from stable block/meta identity; keep resource epoch in cache keys. Use an explicitly controlled legacy RenderBlocks/Tessellator capture path for supported renderers, main-thread budgets for unknown ISBRHs and tile-dependent work, and deterministic fallback appearance for unsupported renderers. TESRs need a separate opt-in/fallback policy. Do not read live worlds/TileEntities on generic workers or promise exact modded appearance from icons alone. Any lower-level GTNHLib capture helper needs a separate pinned audit.

## 7. Optional dependency boundary and compatibility acceptance

1. Baseline artifact must initialize/render/reload/dispose with **no Angelica classes available**. Keep its core interfaces, signatures, fields and static initializers free of Angelica/Iris types.
2. Use a no-op compatibility interface implemented by a lazily loaded bridge only after mod/API availability checks. A version-scoped optional companion module is cleaner for direct typed hooks than distributing shaded copies of APIs. Compile-only must not become a runtime mandatory dependency. @Optional is helpful only where actually supported; it is not a blanket shield for arbitrary static references.
3. Separate capabilities: release-compatible TextureServices + Iris status + HUD event hook; current-only GLState/TESR APIs gated by their API ids/versions. Pin/test the supported release range; mere class presence is not a binary-compatibility promise.
4. Do not fail the whole map if an optional method is missing; log once and disable the affected bridge feature. Do not catch arbitrary rendering failures and pretend the state is sound.
5. Future acceptance tests (not run): no Angelica; 2.1.50 caching off/on; current caching off/on; shader pack off/on and shadow pass; resize/GUI scale; resource reload during pending bake; dimension/world unload; animated icon not visible in terrain; renderer exception cleanup; non-default incoming FBO; state equality before/after offscreen and final composite. All must use the Java 25+lwjgl3ify target baseline without changing the user's instance for research.

## 8. Licensing and reuse limits

The repository [LICENSE](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/LICENSE>) identifies LGPLv3 and inherited attribution. Individual upstream-derived files can have additional notices; preserve and review the exact source lineage before copying. In particular [HUDCaching license](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/src/main/java/com/gtnewhorizons/angelica/hudcaching/LICENSE-HUDCaching.md>) explicitly states **CC BY-NC-SA 4.0** from Patcher; current [HUDCaching license](<https://github.com/GTNewHorizons/Angelica/blob/60d1a3de3c2e30d3b5eee7a4df58ba5d61bfafe4/src/main/java/com/gtnewhorizons/angelica/hudcaching/LICENSE-HUDCaching.md>) retains that separate notice. Therefore “Angelica is open source” is not permission to copy every convenience under a single assumed permissive license. The [model specification](<https://github.com/GTNewHorizons/Angelica/blob/d1e6dc8c9463eda8bab1b80383cac17321b0535a/docs/model-spec.md>) also declares a separate wiki-derived CC BY-NC-SA notice and is not evidence of a working general model-export API.

Prefer runtime calls to narrow optional APIs and independently implemented lifecycle/state/capture abstractions. **Recommended reuse:** texture activity notification, public shader status, a version-tested post-HUD hook, snapshot/epoch design lessons. **Not recommended:** vendoring GLSM, reusing Iris FBO/pipeline ownership, borrowing world mesh buffers, depending on private HUD invalidation, marking unknown renderers thread-safe, or making current TESR APIs a release/baseline requirement.
